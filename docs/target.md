## 2. P07 定位与目标

- **类别**：内存、调度、性能优化。
- **关键词**：预加载、预渲染、路径预测、启动优化。
- **场景**：用户访问路径存在重复规律，例如“首页 → 详情 → 返回 → 下一个详情”。
- **目标**：利用历史访问路径预测下一步最可能进入的页面，在点击前的空闲时间提前取数、预渲染视图，减少点击后的等待。
- **核心权衡**：预测命中收益与资源浪费之间的平衡，不能只追求命中率而忽视内存、计算和当前页面流畅性。
- **涉及领域**：页面生命周期、预渲染与视图复用、资源调度与空闲感知、用户行为建模。

项目实践整体鼓励在 OpenHarmony 内核、驱动、框架等底层技术领域开展系统级创新。P07 应交付可运行、可评测的优化实现，单纯写源码分析或仅在桌面模拟预测算法不能覆盖其完整目标。

## 3. 功能闭环与技术难点（P07 指导）

### 3.1 四个组成模块

| 模块 | 页面给出的职责 | 应能够展示的结果 |
| --- | --- | --- |
| 行为采集 | 记录页面访问序列，脱敏、可关闭，形成路径样本 | 样本来源、采集开关、脱敏方式及访问顺序可核对 |
| 预测模型 | 用一阶/多阶马尔可夫或轻量序列模型预测下一跳 | 有输入路径、预测结果和实际下一跳的对应记录 |
| 预加载执行 | 在系统空闲窗口触发数据预取、视图预渲染，设置取消机制 | 能观察触发时机、预取/预渲染执行、命中复用和取消 |
| 资源回收 | 预测落空或内存紧张时及时释放预加载资源 | 能验证取消与回收后资源释放、页面状态正确 |

评分落点明确要求 **“预测 → 预加载 → 命中 → 回滚”完整闭环，并有真实场景数据**。数据预取与视图预渲染应分别说明实现范围，不能把缓存数据直接称为视图预渲染。

### 3.2 必须处理的难点

1. **空闲执行**：预加载必须在空闲窗口进行，否则会反过来拖慢当前页面。
2. **落空回滚**：预测错误时能够干净回滚，不留下半成品视图。
3. **资源仲裁**：内存紧张时处理预加载与前台业务争抢资源的问题，具有优先级安排和释放策略。
4. **有效评测**：证明点击后耗时确实下降，并同时核对总体成本，不能仅以任务被提前执行来宣称整体效率改善。

### 3.3 本地落实建议（非新增课程硬指标）

- 明确任务生命周期：待执行、执行中、可复用、已命中、已取消、已释放，并处理异步结果晚到等情况。
- 覆盖冷启动无历史、预测失误、重复进入退出、快速切换、资源紧张、采集关闭等情形。
- 分别记录数据预取、视图构建、页面可见/可交互的完成边界，避免混用时间口径。
- 为缓存设置可解释的容量、有效期和淘汰规则，具体数值由设备能力和实测确定。
- 明确预测策略、空闲判定、回收策略中哪些是自己的实现，哪些复用系统能力。
