0为什么这门课鼓励你用 AI 智能体

大模型读代码、画图、归纳的能力已经超过多数初学者。但本课程的对 AI 的立场是：

🔓禁止 AI 是浪费

用智能体追调用链、解释目录职责、生成图初稿——这些它做得比人快。

⚠️全信 AI 是危险

实测第三方 AI 生成的架构文档会把调用链错配到毫不相干的文件，而且看起来完全合理。

🎯考核的是判断力

不是"你能不能生成漂亮文档"（AI 三分钟），而是你能不能带着证据驾驭 AI 的产出。

核心规则：AI 负责「产出」，你们负责「证伪」。每一条写进报告的技术结论，都必须由你们自己回到源码验证，挂上 文件:行号#符号 锚点。锚点对不上 = 结论不成立。

1报告内容：六部分，缺一不可

滚动查看——建议按此顺序推进，前一部分是后一部分的地基。

子系统定位与边界约 2 页

子系统在全景中的位置（哪些仓、装进哪些 SA 进程）；用 bundle.json 与 subsystem_config.json 证明部件归属；与上下游的依赖关系，画出边界图。

总体架构约 3 页

分层结构与目录职责（frameworks/ services/ interfaces/ 各放什么）；目录即进程边界——哪些代码跑在哪个进程、进程间怎么通信（IPC proxy/stub）；SA 注册方式。

类图与协作图约 4 页报告核心

类图：核心继承体系与聚合关系，每个类标注定义锚点。协作图/时序图：至少一条端到端业务链路（应用 API → IPC → HDI），每一跳给锚点。推荐 mermaid，可机读可版本化。

核心设计算法与机制约 4 页

至少深挖 3 个机制：请求-响应关联、状态同步、分发/路由策略、并发保护……每个机制必须回答三问：解决什么问题？怎么解决（锚点）？代价是什么？

设计利弊分析约 3 页

至少 3 条利 + 3 条弊，每条落到代码证据，不接受"高内聚低耦合"这类空话。鼓励记录追链路时被误导、走弯路的真实经历——这是"证伪 AI"最有价值的素材。

AI 协作纪实约 2 页必填特色题

工作流（什么智能体、什么提示策略、怎么分工）；纠错清单（AI 错在哪、你们如何发现）；方法论沉淀。纠错清单是得分项不是扣分项——诚实的"AI 骗了我们三次"比零错误的完美报告得分更高。

3AI 纠错实录：翻卡看真相

以下三例来自电话子系统示范材料的真实验证过程——AI 的说法（正面）vs 源码锚点证伪后的真相（背面）。点击卡片翻转。你们的报告也要产出这样的对照。

🤖 AI 的说法
"cellular_call 与 core_service 之间走 IPC 跨进程调用"

理由：它们是两个独立 SA，"看上去"自然该走 IPC。

👆 点击翻面看源码证据
✅ 锚点证伪
实际是进程内单例直调：cellular_call_connection_cs.cpp:86 直接调 CoreManagerInner::GetInstance().Answer(...)，没有任何 proxy/stub。

教训：SA 相邻 ≠ IPC 相邻，边界必须靠锚点定。
👆 再点翻回
🤖 AI 的说法
"CSControl::Dial 按 SIM 卡运营商决定走 GSM 还是 CDMA 分支"

听起来合理——运营商确实与制式相关。

👆 点击翻面看源码证据
✅ 锚点证伪
判据是当前网络制式，不是运营商：cs_control.cpp:50-56 用 GetNetworkStatus() 返回的 PHONE_TYPE_IS_GSM / PHONE_TYPE_IS_CDMA 分支。

教训：AI 会把"相关概念"当"真实判据"，必须读分支条件原文。
👆 再点翻回
🤖 AI 的说法
"接听电话就是调 Answer 接口，一条直线到 RIL"

时序图初稿确实画成了直线。

👆 点击翻面看源码证据
✅ 锚点证伪
漏掉了三方通话分支：已有活跃通话时接听要先保持当前通话——cs_control.cpp:240-260（注释含 3GPP <stat> 状态表 0–5）先 SwitchCallRequest 再 AnswerRequest。

教训：AI 画的是"主路径"，边界分支要自己挖。
👆 再点翻回

    证据分级（客观刻度，oh_level.py 可机判）：

    • L0 定位：≥3 个有效锚点、覆盖 ≥2 个不同文件、0 失败——只算「找到并锁定」，范例文档即 L0。
    • L1 结构：L0 + 含 mermaid 图 + 锚点跨 ≥2 个顶层目录——画出可信的模块与调用关系。
    • L2 复现：L1 + 日志/观测标记 + ≥1 个带 #符号 的锚点——用现成日志复现已知行为。
    • L3 / L4（研究型加分，需人审）：L2 之上再补 diff / 构建证据（L3）、baseline + 可重复（L4）；脚本只能启发式提示，不算硬分。

    口径说明：本课程「课程报告」在总分里占 20 分，本节 100 分 Rubric 是报告内部的折算刻度；L0–L2 是另一维度的「证据是否扎实」客观检查，两者互补、不重复计分。

    • 交 slides.pdf + .pptx 源文件。缺 PPT / 未按时交 / 汇报缺席 → 该组答辩记 0 分。

    9常见坑（来自学生工具包）

    • 解压别用 Git Bash 的 unzip：会把切片里那张中文名 PNG 写成乱码名。包本身是好的、不影响锚点校验，但 git status 会多一条记录。请用系统自带工具（Windows 资源管理器 / macOS 归档工具 / 7-Zip）解压。
    • 上传 Git 时注意 .git 嵌套：切片目录里保留了浅克隆的 .git（用于核验快照版本）。把整个包放进作业仓库再 git add .，Git 会把切片当成 submodule，别人 clone 下来是两个空目录。要么 find slices -name .git -type d -prune -exec rm -rf {} +，要么写进 .gitignore。
    • 不要 git pull 切片：拉取会让工作区离开快照、行号漂移，全组基线就失效了。要换版本请重新 oh_slice.py --fetch 到新目录。
    • 交付物不用带切片副本：批改只认 report.md / anchors.md / meta.json / slides.pdf，一个 6MB 的切片副本对判定没有帮助。
    • Windows 中文乱码：终端执行 chcp 65001；报告文件保存为 UTF-8。
